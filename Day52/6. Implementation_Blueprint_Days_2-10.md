## 🧭 Project Snapshot (read this first, every day)

- **Product:** AI-powered personal finance analyzer (web app)
- **Users:** Individuals tracking personal expenses (multi-user, email/password auth)
- **Core data:** Transactions with Amount, Date, Category, Description — added manually or via CSV upload
- **AI features:** (1) Auto-categorization, (2) On-demand AI insights, (3) Chat Q&A grounded in user's own data
- **Visuals:** Category pie chart + spending trend chart
- **Time budget:** ~1–2 hrs/day, 9 days remaining
- **Explicitly OUT of scope:** bank API integrations, multi-bank CSV auto-detection, scheduled/email insights, open-ended financial advice, mobile app, social login/email verification
- **Deployment target:** Public web URL, free-tier hosting only

**Golden rule for every day: working and deployed beats big and broken. If short on time, cut a feature — don't ship something half-built.**

## 📤 Day 5 — CSV Upload & AI Auto-Categorization

### 🎯 Objective
Let users bulk-import transactions via CSV upload, and have every transaction (manual or CSV) automatically categorized by the Claude API.

### 📖 What I'll learn
- Parsing CSV files in the browser
- Calling the Claude API from a backend/serverless function (never expose API keys client-side)
- Prompt design for structured, constrained AI output

### 🛠 Features to build
- CSV upload UI with a documented template
- CSV parsing and validation
- AI categorization service (used by both manual entry and CSV import)
- Bulk insert of parsed + categorized transactions

### 📝 Step-by-step implementation plan
1. Define and document the required CSV format: columns `Date, Amount, Description` (exact header names). Create a sample `template.csv` users can download.
2. Install a CSV parsing library (e.g., `papaparse`): `npm install papaparse`.
3. Build `CsvUploadPage.jsx`: file input, parses file client-side with PapaParse, shows a preview table before import.
4. Validate parsed rows: correct columns present, amount is numeric, date is parseable. Reject/flag bad rows with a clear message — do not silently drop them.
5. **Set up a backend/serverless endpoint** (e.g., `/api/categorize`) that calls the Claude API — this keeps your API key server-side, never in frontend code.
6. Design the categorization prompt: send the transaction description (and amount) plus the fixed category list, and instruct Claude to respond with ONLY one category name from that exact list (structured/constrained output — see PRD Feature: Auto-Categorization).
   - Example prompt pattern: *"Categorize this transaction into exactly one of these categories: [list]. Transaction: '{description}', amount: {amount}. Respond with only the category name, nothing else."*
7. For CSV import: after parsing, call the categorization endpoint for each row (or batch them) before inserting into the database.
8. For manual entry (Day 4 form): call the same categorization endpoint automatically when the user leaves the Description field blank on category, OR always suggest a category the user can override — decide based on time remaining; simplest: auto-suggest category as soon as description is entered, user can change it before saving.
9. Insert all categorized rows into `transactions` table via the existing service functions.

### 🐞 Common issues and debugging tips
- **AI returns a category not in the fixed list:** tighten the prompt — explicitly say "respond with ONLY one of these exact strings" and list them; consider a fallback to "Other" if the response doesn't match any valid category.
- **CSV parsing breaks on commas inside descriptions:** PapaParse handles quoted CSV fields correctly by default — make sure the template instructs users to quote descriptions containing commas.

## 💬 Day 8 — Finance Chat (Q&A on User's Own Data)

### 🎯 Objective
Build a chat interface where the user asks direct questions about their own spending and gets accurate answers computed from their real transaction data.

### 📖 What I'll learn
- Designing an AI feature that must be factually accurate, not just fluent
- A basic "data lookup then AI phrasing" pattern (a lightweight form of tool-use/RAG)
- Building a simple chat UI

### 🛠 Features to build
- Chat UI (message input + conversation history)
- Backend logic that translates a user's question into a data query, then asks Claude to phrase the computed answer

### 📝 Step-by-step implementation plan
1. **Key architecture decision (locked in for time-boxing):** rather than letting Claude freely reason over raw data (error-prone and slow), use this reliable pattern:
   - Step A: Send the user's question, along with the current date and a compact summary of available data dimensions (categories, date range), to Claude with instructions to extract structured filters as JSON: `{category, start_date, end_date, aggregation_type}`.
   - Step B: Run the actual computation yourself in code (query/filter the transactions table using those extracted filters) — this guarantees the number is correct.
   - Step C: Send the computed result back to Claude with the original question, asking it to phrase a short, natural answer using that exact number.
2. Build `/api/chat` endpoint implementing steps A–C above.
3. Build `ChatPage.jsx`: simple message list + text input, sends question to `/api/chat`, displays the returned answer as a chat bubble.
4. Keep conversation history in local component state for the session (no need to persist chat history to the database for v1.0 — confirm this is acceptable given time budget).
5. Add a few suggested example questions as clickable chips (e.g., "How much did I spend on food this month?") to guide users and make demoing easy.
6. Handle ambiguous or unanswerable questions (e.g., asking about data outside the stored range) with a graceful clarifying response instead of a wrong number.

### 📂 Files and folders to create or modify
```
/api/chat.js  (or equivalent backend route)
/src/services/aiChat.js
/src/pages/ChatPage.jsx
/src/components/ChatBubble.jsx
/src/components/SuggestedQuestions.jsx
```

### 🔗 APIs, libraries, services, or tools to integrate
- Anthropic Claude API (server-side, two calls per question — extraction then phrasing, as described above)

### 🧪 Testing tasks
- Ask at least 5 varied real questions against your sample data and manually verify each answer is numerically correct:
  - "How much did I spend on food this month?"
  - "What was my biggest expense category last month?"
  - "How many transactions do I have in Transport?"
  - "How much did I spend in total in [specific month]?"
  - "What did I spend on [description keyword]?"
- Ask an out-of-scope question (e.g., "Should I invest in stocks?") and confirm it responds with a graceful "I can only answer questions about your spending data" instead of hallucinating advice.

### 🐞 Common issues and debugging tips
- **Wrong numbers in answers:** confirm Step B (your own code) is doing the actual math, not Claude — Claude should only phrase, never calculate, the final figure.
- **Filter extraction fails on vague questions:** add a fallback — if extraction returns incomplete filters, ask a clarifying question back to the user instead of guessing.
- **Chat feels slow:** two sequential AI calls add latency; if this is a problem, combine into a single call using structured output and compute before responding, if your chosen library supports it. Otherwise, accept the latency — correctness matters more than speed here.
