# API Design — AI-Powered Personal Finance Analyzer
### Day 2 Deliverable | AB Talks 60-Day Claude AI Challenge Capstone

> No implementation yet — this document defines every custom endpoint needed for v1.0.

---

## 0. API Strategy

Standard transaction CRUD (add, edit, delete, list) does **not** need custom backend endpoints. The Supabase client SDK talks directly to Postgres from the browser, with Row-Level Security enforcing that users can only ever read/write their own rows (see `SCHEMA.md`). Building a custom REST layer for CRUD would be redundant work for no added security or functionality.

Custom serverless endpoints are needed **only** where the Anthropic Claude API must be called — because the API key must never be exposed to the browser. That's exactly three endpoints, matching the three AI features in the PRD.

---

## 1. `POST /api/categorize`

**Purpose:** Categorize one or more transactions using Claude, constrained to the fixed category list. Used by both manual entry (single item) and CSV import (batch).

**Authentication:** Required. Supabase session JWT in `Authorization: Bearer <token>` header, verified server-side before processing.

**Request Body:**
```json
{
  "transactions": [
    { "description": "Uber ride", "amount": 18.50 }
  ]
}
```

**Response (200 OK):**
```json
{
  "results": [
    { "description": "Uber ride", "category": "Transport" }
  ]
}
```

**Validation:**
- `transactions` must be a non-empty array
- Each item requires `description` (string, 1–255 chars) and `amount` (number)
- Array length capped at 100 items per call (batch size limit for CSV imports)

**Error Cases:**
| Status | Condition |
|---|---|
| 400 | Missing/invalid fields, empty array, or array exceeds 100 items |
| 401 | Missing or invalid auth token |
| 422 | Claude returned a category outside the fixed list — server falls back to `"Other"` and logs for review (never fails the request) |
| 500 | Claude API call failed — return any partial results already processed |

## 2. `POST /api/insights`

**Purpose:** Generate an on-demand, natural-language summary of the user's spending patterns from their own aggregated data.

**Authentication:** Required. Supabase session JWT.

**Request Body:**
```json
{ "userId": "uuid" }
```
Note: the backend re-queries and re-aggregates the user's transactions server-side — it never trusts a client-supplied aggregate, to prevent tampering or stale data.

**Response (200 OK):**
```json
{ "insight": "You spent 22% more on Bills this month, mostly due to a utilities increase." }
```

**Validation:**
- `userId` must exactly match the authenticated session's user id — prevents requesting another user's insights even if the id were guessed

**Error Cases:**
| Status | Condition |
|---|---|
| 401 | Unauthorized, or `userId` doesn't match the session |
| 422 | Insufficient data (fewer than 3 transactions) — returns a friendly "add more transactions to unlock insights" message instead of calling Claude |
| 500 | Claude API call failed |

---

## 3. `POST /api/chat`

**Purpose:** Answer a direct, natural-language question about the user's own transactions. Uses a two-step pattern (extract filters → compute in code → phrase answer) so Claude never performs the actual math — see `ARCHITECTURE.md` §2.3 for the full sequence diagram.

**Authentication:** Required. Supabase session JWT.

**Request Body:**
```json
{
  "userId": "uuid",
  "question": "How much did I spend on food in June?"
}
```

**Response (200 OK):**
```json
{ "answer": "You spent $312.40 on Food & Dining in June." }
```

**Validation:**
- `question`: non-empty string, max 300 characters
- `userId` must match the authenticated session's user id

**Error Cases:**
| Status | Condition |
|---|---|
| 401 | Unauthorized, or `userId` doesn't match the session |
| 422 | Question couldn't be mapped to a valid filter — returns a clarifying response (e.g. "Could you specify a category or time period?") rather than guessing |
| 500 | Claude API call or database query failed |

---

## 4. Shared Conventions (all endpoints)

- **Auth:** every request requires `Authorization: Bearer <supabase_jwt>`; verified server-side as the first step before any other logic runs.
- **Response shape:** success → `{ ...data }`; error → `{ "error": "human-readable message" }`, paired with the correct HTTP status code.
- **Secrets:** the Anthropic API key is read only from Vercel environment variables (`ANTHROPIC_API_KEY`). It is never accepted as a request parameter, never returned in a response, and never logged.
- **Rate/size limits:** categorize batches capped at 100 items; chat questions capped at 300 characters — both to keep Claude calls fast and predictable within the free-tier/low-cost budget.
