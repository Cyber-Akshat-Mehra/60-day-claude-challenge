📘 How this was built ▾

System prompt design

The assistant runs as a single Claude system prompt with two response modes, both returning strict JSON so the UI can render structured score dials and STAR breakdowns instead of freeform chat text:

  • generate_question — takes role + level + question count, returns one behavioral question the candidate hasn't seen yet, tagged with the competency it probes (e.g. "conflict resolution").
  • score_answer — takes the question + candidate's raw answer, returns a 1–10 score, a one-line verdict, a STAR presence check (S/T/A/R each marked present or missing), 2–3 strengths, 2–3 improvement notes, and a rewritten model answer excerpt.

Edge-case handling built into the prompt

  • Off-topic or nonsense input → the model is instructed to still return valid JSON, set score to null, and explain in the verdict field that it couldn't evaluate the response, rather than breaking the UI contract.
  • Very short / empty answers → scored low with feedback specifically about needing more detail, not a generic error.
  • Abuse or attempts to jailbreak the coach persona → model stays in character, declines, and redirects to interview practice.
  • Ambiguous role input → model infers the closest reasonable professional interpretation rather than refusing.

Why the UI looks like this

A generic chat bubble UI hides the thing job-seekers actually want: a fast, visual verdict. So the interface is built around a score dial (instant read on quality), a STAR checklist (the exact rubric real interviewers use), and a model answer block (concrete "here's better" reference) — closer to a coaching report than a chatbot transcript. The serif/navy/gold palette borrows from executive-coaching and premium-publishing aesthetics to feel credible rather than gimmicky.

Extending this assistant

  • Memory across sessions: persist question history + scores to localStorage or a backend so returning users see progress trends over time.
  • Voice mode: swap the textarea for the Web Speech API so users can practice answering out loud, then transcribe before scoring.
  • Multi-step flow: add a "mock interview" mode that chains 5 questions with no feedback shown until the end, closer to a real interview.
  • Tools: connect a resume-upload tool so questions and scoring reference the user's actual experience, or a job-description tool to tailor competencies to a real posting.
  • Difficulty adaptation: feed prior scores back into the generate_question call so weak competency areas get re-tested.
