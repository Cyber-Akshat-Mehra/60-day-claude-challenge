Why output quality varies (and how this fixes it)

Inconsistent AI output is almost always a missing-ingredient problem: the model wasn't given a fixed role, clear constraints, or a defined output format, so it improvises differently each time. The fix isn't a better one-off prompt — it's a repeatable structure you reuse every time you ask for that kind of thing. That's what the workflows and builders below are: fill-in-the-blank structures, not one-time prompts.

Loop Builder

A "loop prompt" is a prompt that tells the AI to check its own work against criteria and keep revising until it meets them or hits a stop condition — instead of giving you its first draft as the final answer. Paste any normal prompt below, define what "done" looks like, and get back a self-correcting version.

1Goal

What does success look like at the end of the loop? This anchors every revision so the AI doesn't drift.

2Evaluation criteria

The checklist the AI grades its own draft against before showing it to you. Pick as many as apply.

3Improvement strategy

How the AI should revise between iterations when it finds a gap.

4Stop conditions

When the loop should end. Without this, loops can run forever or quietly degrade — always set at least one.

5Safety rules

Guardrails so autonomous iteration doesn't do something you didn't ask for, like changing scope or fabricating results.

My Workflows

        
Editable, reusable prompt templates for your recurring tasks (code review, debugging, refactors, learning new tech). Each has variables in brackets like [LANGUAGE] you fill in before copying.

      

      

        
Prompt Builder

        
Build a prompt from scratch by adding structural pieces — role, objective, context, constraints, reasoning strategy, output format, tone, examples, quality checks. Each block explains what it does and why it changes the output. A live preview assembles them into one final prompt as you go.

      

      

        
Loop Builder

        
Turns a normal, single-answer prompt into a self-checking one. You define a goal, a checklist the AI grades itself against, how it should revise between attempts, and when it must stop. This is useful for tasks where "good enough on the first try" isn't reliable, like a thorough code review.

      

      

        
Building Blocks

        
A reference library explaining every block used across both builders, so you understand the "why," not just the "what."
