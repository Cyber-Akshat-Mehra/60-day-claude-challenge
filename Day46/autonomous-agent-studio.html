Agent responsibilities & information flow

01 Planner

Reads the problem once, breaks it into an implementation plan (approach, edge cases, function signature) that seeds the first Executor call.

02 Executor

Writes the actual code draft. Round 1 uses the Planner's plan; every later round receives the prior draft + Improver's rewrite instructions.

03 Evaluator

Scores the current draft 0–100 against the rubric (correctness, quality, efficiency, robustness) and returns a structured report. This score drives the stop-check.

04 Critic

Independently reviews the same draft for concrete flaws — bugs, missed edge cases, style issues — feeding specific, actionable notes forward.

05 Improver

Takes evaluation + critique + prior draft and produces the next draft. Its output becomes next round's "current draft."

06 Memory Manager

After each round, distills what changed and what was learned into a short memory note, carried forward so agents don't repeat mistakes.

07 Safety Monitor

Screens each draft for unsafe code patterns before it can be marked final.

08 Final Reviewer

Runs once, after a stop condition fires, to sign off on the winning draft and write the human-readable summary.

The stop-check is what actually governs the loop: after every Evaluator call, the orchestrator checks (in order) plateau → threshold → hard cap. Whichever fires first ends the Evaluator→Critic→Improver cycle and branches execution to the Final Reviewer. Nothing about round count is decided in advance.

Architecture overview

  • Single HTML file, vanilla JS orchestrator, no build step, no external libraries.
  • Every agent is a distinct fetch call to /v1/messages with its own system prompt and the minimal state it needs (never the full transcript).
  • A history[] array is the single source of truth: each entry holds {round, draft, score, evalReport, critique, memoryNote, delta} and drives every rendered panel.
  • Retry logic wraps every call with exponential backoff and a visible retry counter; failures degrade gracefully without crashing the loop.

Extension ideas

  • Add a Test Writer agent that generates unit tests each round and feeds pass/fail counts into the rubric.
  • Add a Human-in-the-loop gate: pause before Final Reviewer and let a person accept, reject, or request one more round.
  • Persist history[] to localStorage so a run can be resumed after a page reload.
  • Swap the domain: point the same Planner→Executor→Evaluator→Critic→Improver skeleton at prose, SQL, or infra-as-code tasks.

Further prompts to extend this system

  • "Add a Test Writer agent that runs between Executor and Evaluator, generates pytest cases, and passes results into the rubric."
  • "Add a branch where, if Safety Monitor flags an issue, the loop routes back to Improver with a mandatory fix instruction before Evaluator runs again."
  • "Turn this into a multi-task queue that runs the whole pipeline over a list of problems and produces a comparison report."
  • "Add streaming token-by-token rendering of the Executor's draft as it's generated."
